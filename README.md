# 三国杀 · 网页联机版

支持**局域网联机**、**开房间**、**添加人机队友/对手**，并**根据房间人数自动配置身份**的三国杀网页游戏。电脑端与手机端（含平板）均可直接游玩，界面自适应。

---

## 一、快速开始

### 1. 安装依赖

```bash
npm install
```

### 2. 启动服务

**方式 A：一键启动（推荐，不用进终端）**

双击项目目录下的 **`启动三国杀.bat`**（Windows）或 **`启动三国杀.command`**（macOS / Linux）：

- 自动检测 Node.js（未安装会给出下载地址）
- 首次运行自动执行 `npm install`
- 自动打开浏览器
- 窗口里直接显示局域网访问地址，发给朋友即可
- **服务已经在别处启动时不会再报端口占用错误**，而是直接打开浏览器

**方式 B：终端启动**

```bash
npm start
```

启动后控制台会输出访问地址，例如：

```
============================================
  三国杀联机服务已启动
============================================
  本机访问：  http://localhost:3000
  局域网访问：http://192.168.3.37:3000   （同一 Wi-Fi 的手机/电脑可直接打开）
```

### 3. 开始游戏

| 步骤 | 操作 |
| --- | --- |
| 1 | 房主在本机浏览器打开 `http://localhost:3000`，填写昵称，点击**创建房间** |
| 2 | 其他玩家在同一局域网的设备上打开 `http://<房主IP>:3000`，填写昵称并输入**房间号**加入 |
| 3 | 房主点击**复制邀请**可复制房间号与链接发给其他人 |
| 4 | 人数不足时，房主通过**人机数量**的 ＋ / － 按钮添加或移除电脑玩家 |
| 5 | 房主点击**开始游戏**，每人从 5 名候选武将中选择其一（30 秒未选将自动选择） |

> **手机无法连接时**：请检查 Windows 防火墙是否放行了 Node.js / 3000 端口。
> 可临时关闭防火墙，或新建入站规则允许 TCP 3000 端口。

### 修改端口

```powershell
# Windows PowerShell
$env:PORT=8080; npm start
```

```bash
# macOS / Linux
PORT=8080 npm start
```

### 停止服务

- 关闭运行服务的那个窗口即可；
- 若服务在后台运行（看不到窗口），双击 **`停止三国杀.bat`**（Windows）或 **`停止三国杀.command`**（macOS / Linux）。
  它会按命令行精确匹配本项目启动的 `node server.js` 进程并结束它，**不会影响其它 node 程序**，完成后还会确认端口已释放。

| 2 | 1 | 0 | 1 | 0 |
| 3 | 1 | 1 | 1 | 0 |
| 4 | 1 | 1 | 1 | 1 |
| 5 | 1 | 1 | 2 | 1 |

| 7 | 1 | 2 | 3 | 1 |
| 8 | 1 | 2 | 4 | 1 |
| 9 | 1 | 3 | 4 | 1 |
| 10 | 1 | 3 | 4 | 2 |

- **主公**身份公开，且体力上限 +1。
- 其余身份暗置，角色**阵亡后自动亮明**。
- 胜负判定：主公阵亡则反贼获胜（若仅剩内奸一人则为内奸获胜）；反贼与内奸全部出局则主公与忠臣获胜。

## 三、已实现内容

### 卡牌（共 149 张 / 40 种）

- **基本牌**：杀（31）、闪（20）、桃（12）、酒（7）、**火杀（4）、雷杀（4）**
- **锦囊牌**：决斗、南蛮入侵、万箭齐发、顺手牵羊、过河拆桥、无中生有、五谷丰登、桃园结义、借刀杀人、无懈可击、**火攻（4）**
- **延时锦囊**：乐不思蜀、**兵粮寸断**、闪电
- **装备**
  - 武器：诸葛连弩、青釭剑、雌雄双股剑、贯石斧、青龙偃月刀、丈八蛇矛、方天画戟、麒麟弓、**寒冰剑、古锭刀、朱雀羽扇**
  - 防具：八卦阵、仁王盾、**藤甲、白银狮子**
  - 坐骑：8 匹（±1 马，含骅骝、快航）

**新增卡牌的效果均已完整实现：**

| 卡牌 | 效果 |
|---|---|
| 火杀 / 雷杀 | 火焰 / 雷电属性的【杀】。可破【藤甲】，对【藤甲】角色火焰伤害 +1 |
| 兵粮寸断 | 置于距离 1 以内角色的判定区，判定**不为梅花**则跳过其摸牌阶段 |
| 火攻 | 目标展示一张手牌，你弃置一张同花色手牌，对其造成 1 点火焰伤害 |
| 寒冰剑 | 你用【杀】造成伤害时，可防止该伤害，改为弃置目标两张牌 |
| 古锭刀 | 你用【杀】对**没有手牌**的角色造成伤害时，伤害 +1 |
| 朱雀羽扇 | 你可以将普通【杀】当火焰【杀】使用 |
| 藤甲 | 【南蛮入侵】/【万箭齐发】/ 普通【杀】对你无效；受到火焰伤害时 +1 |
| 白银狮子 | 每次受到大于 1 点的伤害时防止多余伤害；失去它时回复 1 点体力 |

> 尚未收录：铁索连环（需要连环状态与属性伤害传导）、无懈可击的连锁抵消等较复杂机制。

### 武将（标准包 22 名）
- **蜀**：刘备、关羽、张飞、赵云、马超、诸葛亮、黄月英
- **魏**：曹操、司马懿、夏侯惇、郭嘉、许褚、甄姬
- **吴**：孙权、周瑜、黄盖、吕蒙、陆逊、孙尚香
- **群**：貂蝉、吕布、华佗

全部武将技能均已实现，包含主公技（激将、护驾、救援）。

### 规则
回合流程、判定区结算、距离与攻击范围、伤害结算、濒死求桃、阵亡奖惩（杀反贼摸三张、主公误杀忠臣弃光）、无懈可击、装备替换等。

- **濒死救援**：可用【桃】救任意角色；**自己濒死时也可用手牌中的【酒】自救**（酒只能救自己，不能救别人）。
- **胜负判定**
  - 反贼与内奸全部阵亡 → 主公与忠臣获胜
  - 主公阵亡时，只有「其他存活角色全是内奸」才算内奸获胜（内奸人数可为多名）
  - **只要还有忠臣存活，主公阵亡一律判反贼获胜**（即使反贼已全部阵亡）
  - 反贼全灭但内奸尚存 → 游戏继续
- **弃牌阶段**：只需保证最终手牌数不超过体力值，可弃任意张（也可全部弃光）。

### 人机
电脑玩家会根据自身身份推理敌我关系，并结合场上行为（谁攻击了谁）动态调整判断，支持出牌取舍、响应杀/闪/桃/无懈、技能发动与判定改判。

## 四、界面与操作

### 牌桌布局

所有参与者（含你自己）**环绕显示在屏幕四周**，按座位顺序排列，你固定在正下方。屏幕中央为牌桌，依次显示：

`牌堆（剩余张数）` → `出牌舞台（展示刚打出的牌）` → `弃牌区（张数与最后一张）`

座位会根据屏幕尺寸与人数自动缩放，满员 10 人局在手机上也不会相互重叠。

### 操作

- **出牌**：点击手牌 → 若该牌有多种用法则先选择用法 → 点击目标角色（红框高亮）→ 点击**确定出牌**。
- **结束回合**：点击**结束回合**。
- **弃牌阶段**：只需保证最终手牌数不超过体力值——**可以弃掉任意张**（甚至全部弃光），最少弃到与体力值相等即可。
- **响应**：轮到你需要响应时（出闪、出杀、出桃救人、使用无懈可击等），底部会弹出提示条与可选卡牌，选择或点击**放弃**。
- **技能**：出牌阶段可发动的主动技能按钮会高亮，点击即可发动。
- **日志**：点击右上角**日志**查看战斗记录（侧滑面板）。

### 查看卡牌与武将

- **查看卡牌效果**：点击任意手牌右上角的 **?** ，或点击任意角色（含自己）的**装备牌 / 判定牌**标签，即可看到该牌的完整效果说明。
- **查看对手武将**：点击任意角色的**武将名**或其右侧的 **?**，可查看该武将的全部技能说明，以及体力、手牌数、攻击范围、装备等状态。未公开的身份不会显示。
- 武将详情里的装备仍可继续点击查看，弹窗可点空白处或**关闭**按钮退出。

### 动画与音效

- **出牌动画**：任何人打出牌时，中央舞台会弹出该牌并标注出牌者与目标，随后淡出。
- **扣血动画**：受到伤害时对应座位红光闪烁、左右震动，同时体力数字放大变红，并飘出 `-N`；该动画会跨界面刷新保留，不会一闪即逝。
- **回血 / 阵亡**：回复体力飘出 `+N` 并绿光闪烁；阵亡时座位灰化。
- **判定**：判定牌会在中央停留约 **3 秒**，带金色光晕呼吸效果；判定结束后弹出醒目结果卡，明确显示「**【乐不思蜀】在 XXX 身上判定 —— 生效 / 失效**」及具体原因（红桃失效、梅花失效、黑桃 2~9 命中……）。闪电、兵粮寸断、乐不思蜀以及铁骑、刚烈、洛神、八卦阵等技能判定都有对应动画。
- **五谷丰登**：先把翻出的所有牌向全场**公示 1 秒**，之后才开始依次选牌。
- **被询问时保持展示**：例如 A 对 B 使用【顺手牵羊】、询问 B 是否打出【无懈可击】期间，牌桌上会**一直显示**「A 对 B 使用【顺手牵羊】」，询问结束才撤下。其他牌同理。
- **过河拆桥公示**：被弃置的牌会向全场展示（红色边框），所有人都能看到拆掉了哪张牌。
- **装备区分**：装备栏按槽位着色加边框（武器橙、防具蓝、+1 马绿、-1 马紫），一眼可辨。
- **音效**：使用浏览器 Web Audio 实时合成，**无需任何音频文件**。出牌、杀、闪、伤害、回血、阵亡、判定、回合、胜负各有不同音效；轮到你或你濒死时会有提示音。
- 点击右上角 **🔊 音效** 可随时开关，状态会记住。尊重系统「减弱动态效果」设置。

### 信息公开

以下信息会**向房间内所有人实时公布**，方便所有玩家同步判断局势：

- **当前在等什么、还剩多久**：顶部常驻倒计时 `⏱ 12s`；中央显示「等待人 · 操作说明 · 剩余秒数」。倒计时最后 5 秒转为红色紧急样式。
- **出牌阶段倒计时**：轮到某人的出牌阶段时，该玩家的操作栏内会直接显示剩余秒数，避免超时被自动结束回合。
- **无懈可击询问**：每次询问是否使用无懈可击时，全场弹出横幅说明要抵消哪张锦囊。**锦囊的使用者本人不会被询问**（不会自己抵消自己的牌）。
- **濒死救援**：角色濒死时全场提示，并公布「是否有人使用【桃】救援 XXX」。
- **房间号**：进入对局后顶部仍显示房间号，方便中途邀请他人。

### 判定与动画

- 同时出现多个判定时会**横向并列展示**，互不重叠，每个都标注「什么牌在谁身上判定」。
- 出牌动画与判定结果分处上下两行，**不会挤在一起**；当同屏同类特效超过 3 张时会自动移除最早的，避免连续出牌时堆成一排。
- 询问响应期间，牌桌上会**常驻**展示引发询问的那张牌（例如「A 对 B 使用【顺手牵羊】」），不会被新动画盖住。

> **匿名询问**：当系统在询问某位角色是否打出【杀】/【闪】/【桃】/【无懈可击】时，其他人只能看到「有角色 · 询问是否有人打出【闪】」，**不会被告知正在询问的是谁**（仅出牌阶段、选择目标等非响应类操作会显示行动者）。
> 所有公开提示都不包含私有信息（如玩家手上的可选手牌），测试中有专门断言校验。

> 首次点击页面后浏览器才允许播放声音，这是浏览器的自动播放策略，属正常现象。

```bash
# 引擎冒烟：8 人局 × 10 局纯人机对局

# 端到端联机：真人 + 人机走完 房间 → 选将 → 对局 → 结算（需先启动服务）

npm run test:ui

# 牌堆构成与新卡牌效果（无需启动服务）
npm run test:cards

# 规则：胜负判定、濒死用酒自救、端口占用处理（无需启动服务）
npm run test:rules
```

> `test:e2e` / `test:fx` / `test:ui` 需要先启动服务（`npm start` 或双击一键启动脚本）。

端到端与特效测试默认模拟 2 名真人 + 2 名人机，可通过环境变量调整：

```powershell
# Windows PowerShell：3 名真人 + 2 名人机
$env:HUMANS=3; $env:AIS=2; npm run test:e2e
```

测试会自动校验：身份配置数量正确、对局中他人身份不泄露（仅公开主公与已阵亡者）、结算后全部身份公开、所有客户端均收到状态推送与特效事件、特效事件字段完整且序号递增。

前端测试基于 jsdom 驱动真实 DOM，会断言：座位环绕分布且互不重叠、自己固定在正下方、出牌时中央弹出正确的牌与出牌者/目标、伤害与回血飘字数值正确、点击卡牌与武将能弹出完整说明、未知特效事件不会导致前端异常。

## 六、服务端接口

### HTTP

| 接口 | 说明 |
| --- | --- |
| `GET /api/net` | 网络地址接口：返回本机可供局域网设备访问的地址列表 |
| `GET /healthz` | 健康检查：`{ ok, rooms }` |

`GET /api/net` 响应示例：

```json
{
  "ok": true,
  "port": 3000,
  "host": "192.168.3.37:3000",
  "hostname": "DESKTOP-XXX",
  "ips": ["192.168.3.37"],
  "interfaces": [{ "address": "192.168.3.37", "iface": "WLAN" }],
  "primary": "192.168.3.37",
  "urls": ["http://192.168.3.37:3000"],
  "lanUrl": "http://192.168.3.37:3000",
  "localUrl": "http://localhost:3000",
  "time": 1750000000000
}
```

- `ips` 已按「最可能被同一 Wi-Fi 设备访问」排序（`192.168.*` > `10.*` > `172.16~31.*`），并过滤掉回环与 APIPA（`169.254.*`）地址。
- `primary` / `lanUrl` 为推荐地址，可直接用于生成邀请链接；`localUrl` 为本机访问地址。

### Socket.IO 事件（服务端 → 客户端）

| 事件 | 说明 |
| --- | --- |
| `room` | 房间状态（大厅 / 选将 / 对局人数、身份配置、武将候选等） |
| `game` | 对局状态，按座位下发，私有信息（手牌、非公开身份）仅本人可见 |
| `fx` | **特效 / 音效事件**，与状态推送分离，用于出牌动画、飘字与音效 |

`fx` 事件由服务端在对局过程中主动广播给房间内所有真人客户端，统一附带：

```json
{ "type": "play", "seat": 2, "as": "slash", "card": { "cn": "杀", "suit": "spade", "num": 7 },
  "targets": [0], "roomId": "A3K9", "seq": 42, "ts": 1750000000000 }
```

- `seq` 在同一房间内**严格递增**，客户端可据此排序、去重与丢弃过期事件；`ts` 为服务端时间戳。
- 事件类型：

| type | 含义 | 主要字段 |
| --- | --- | --- |
| `play` | 出牌（含使用锦囊、装备、桃、酒、无懈可击、青龙偃月刀续杀） | `seat` `as` `card` `extra[]` `targets[]` |
| `respond` | 响应打出（闪 / 杀 / 无懈 / 主公技替出） | `seat` `as` `card` `convert` `forSeat` `skill` |
| `skill` | 发动武将技能 | `seat` `skill` `cn` |
| `damage` | 受到伤害 | `seat` `amount` `source` `reason` |
| `heal` | 回复体力 | `seat` `amount` |
| `dying` | 进入濒死，开始求桃 | `seat` `hp` |
| `die` | 阵亡（同时公开身份） | `seat` `role` |
| `judge` | 判定（乐不思蜀 / 闪电 / 八卦阵 / 铁骑） | `seat` `card` `reason` |
| `draw` | 摸牌（只广播张数，不泄露牌面） | `seat` `count` |
| `discard` | 弃置手牌（只广播张数） | `seat` `count` `from` |
| `equip` / `unequip` | 装备上阵 / 被卸下 | `seat` `slot` `card` `replaced` |
| `turn` | 回合开始 | `seat` `round` |
| `over` | 对局结束 | `winner` |

> 特效事件只负责表现层，不参与任何规则结算；断线重连的客户端不会补收历史特效，而是直接以最新的 `game` 状态对齐。

## 七、项目结构

```
server.js              联机服务入口（Express + Socket.IO）
src/
  cards.js             卡牌数据与牌堆构成
  heroes.js            武将与技能元数据

```

服务端为**权威结算**：所有随机与规则判定均在服务端完成，客户端只负责展示与提交操作，避免作弊与状态不一致。玩家私有信息（手牌、非公开身份）按座位分别下发。

游戏事件与动画通过独立的 `fx` 频道推送（含自增 `seq`，可用于排序与去重），与 `game` 状态推送解耦，因此动画不会被频繁的状态刷新打断。所有 `fx` 事件**只影响表现**，不参与任何规则判定。

调试排错时可设置环境变量 `SGS_DEBUG=1`，引擎会在每次广播时校验牌张是否同时存在于多个区域并打印调用栈。
